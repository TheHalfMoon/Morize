## Live truth

Live repository/GitHub state overrides stale summaries.

Never invent tests, CI, reviews, benchmark results, source revisions, runtime evidence, compatibility, costs, or release readiness.

## SpecGrain

Broad roadmap phases are not implementation authority.

Use the canonical `.specgrain` project. Progressively refine DRAFT specifications until a dependency-eligible leaf satisfies Grain readiness with explicit outcome, scope, acceptance, dependencies, risk/recovery, context budget, change surface, and evidence.

Do not manually label broad work as GRAIN merely to start coding.

## Diffcipline

Every implementation Grain uses proof-before-done semantics.

`NOT RUN != PASS`

The exact diff, risk profile, verification commands/results, dependency/lockfile state, and policy provenance must be inspectable at the exact implementation revision.

## Architecture

- Model output is candidate evidence, not authority.
- Canonical memory survives derived-index loss.
- Authorization precedes disclosure.
- Persistent changes are versioned and recoverable.
- Optional provider/model/vector/graph systems remain replaceable adapters.
- Local/self-hosted operation remains first-class.
- Future managed Morize services may be paid.
- Founder-zero-burn means no mandatory recurring founder-paid dependency without explicit budget authority; it does not mean users must receive every service free.

## Licensing and source reuse

Morize is Apache-2.0.

Source reuse follows `docs/DONOR_AND_PROVENANCE.md`. Do not bulk-copy donors. Pin exact source state, preserve applicable obligations, select the smallest useful component, review hidden hosted/security behavior, and prove the Morize integration independently.

## Completion

A task is complete only when its exact acceptance/evidence requirements are satisfied. Stronger risk requires stronger proof. Do not weaken tests, scope, security, recovery, accessibility, or compatibility just to obtain a PASS.
